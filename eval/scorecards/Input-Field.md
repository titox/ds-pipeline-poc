## To fix in code
None of these gates a criterion.
- `src/figma/primitives/InputField.figma.ts:26-31` `description` is only emitted when Has Label is true. With Has Label=false and Has Description=true Figma shows the description and `InputField` renders one (measured: description 8px below the input, id in `aria-describedby`), but the snippet drops it. Expected: map Has Description independently of Has Label.
- `src/figma/primitives/InputField.figma.ts:17` the `placeholder` enum has a key `default: "I am a placeholder..."`. Value Type has no such option ("Default", "Placeholder") and the text is not in Figma. Expected: remove the key so that Value Type=Default emits no placeholder. How the published template treats this key was not verified.
- `src/ui/primitives/Fieldset/Fieldset.tsx:67-70` the rendered error message is `<span class="error-message" id slot="errorMessage">` with no `role` and no `aria-live`. The contract asks for a live region; the live Figma description says the error is announced when the field is invalid. It is linked through `aria-describedby` only. Expected: a live region, or agree with the designer that `aria-describedby` is enough and update the specification.

## Design issues (for the designer)
- Placeholder text, variants "Value Type=Placeholder": Text/Default/Tertiary on Background/Default/Default is 2.1:1 in light (#b3b3b3 on #ffffff) and 3.78:1 in dark (#ffffff at 40% on #1e1e1e). Minimum 4.5:1. This is what fails criteria 5 and 6.
- Default border, variants "State=Default": Border/Default/Default is 1.41:1 in light (#d9d9d9 on #ffffff) and 1.71:1 in dark (#444444 on #1e1e1e). Minimum 3:1 for the boundary of a control; the input background equals the page background, so the border is the only boundary. This also fails criteria 5 and 6.
- Error layer colour: in the eight variants that are not State=Error the Error text is bound to Text/Default/Default (#1e1e1e), so Has Error=true with State=Default, Hover, Focus or Disabled shows a black message. In code the message is always Text/Danger/Default (#900b09 / #fdd3d0), including on a focused or disabled invalid field.
- Layer sizing: Description is a fixed 240 x 22 and Error a fixed 37 x 22 inside a 120px wide component, while Label and Input are Fill. A longer text will not wrap in Figma. In code both wrap.
- Stroke alignment: the Input frame stroke is Center (1px, 2px on Focus), so the drawn box is 0.5px (1px on Focus) outside the 40px frame on each side. The code draws it inside the 40px box. Confirm Inside is intended.
- Focus on an Error field changes the border from 1px #900b09 to 2px #ec221f, red to red, with no separate ring.
- Disabled, for information (exempt): value text 1.49:1 in light (#b3b3b3 on #d9d9d9); in dark the border is 1.2:1 against the input background (#444444 on #383838).

## Contract differences (export of 24 November against live Figma)
- Description position: the contract property text says "between the label and the input". Live layer order in all 10 variants is Label, Input, Description, Error, and the live description says "stacked in that order". The code follows live Figma.
- Component description: the contract says "`<Input>` when Has Label is false". The live description says to keep `<InputField>` and pass `aria-label`. The Code Connect file follows live Figma.
- The contract says the error message "needs a live region". The live description says React Aria announces the error. See "To fix in code".
- Tokens: the 13 colour, 3 spacing, 3 border and 5 typography entries in the contract are the same variables found bound in live Figma.
- `docs/components/Input-Field.md` and `.contract.json` should be exported again.
