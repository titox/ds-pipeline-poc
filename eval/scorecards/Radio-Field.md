## Design issues (for the designer)
None of these makes a rubric criterion fail; the code reproduces Figma exactly. They are measured weaknesses of the design itself.
- Error is shown by colour alone when Has Error is off (its default). Variants `3174:12708` (Error, Checked) and `3174:12716` (Error, Unchecked): the only change from Default is the 1px border colour, Border/Danger/Default against Border/Brand/Default or Border/Brand/Tertiary. Measured difference between the two border colours: light 1.49:1 (checked), 2.04:1 (unchecked); dark 1.25:1 (checked), 1.54:1 (unchecked). WCAG 1.4.1 Use of Colour needs a cue other than colour, or at least 3:1 between the two colours. Showing the Error Row by default in the Error variants would solve it.
- Focus on an unchecked radio differs from rest almost only in hue. Variant `3111:4277` (Focus, Unchecked): ring Border/Focus/Default `#ec221f` against the resting border Border/Brand/Tertiary: 1.06:1 in light, 2.08:1 in dark, plus 1px of extra thickness, all inside the 16px circle. The ring itself passes the 3:1 non-text minimum against the page (4.36:1 light, 3.82:1 dark), so the rubric is met; the 3:1 change of contrast asked by WCAG 2.4.13 Focus Appearance (AAA) is not.
- Focus ring against the checked fill in dark. Variant `3111:4267` (Focus, Checked): `#ec221f` against Background/Brand/Secondary `#444444` is 2.23:1 (under 3:1) on its inner edge; the outer edge against the page is 3.82:1, which is what keeps it passing.
- Focus and Error both use a red border (`#ec221f` 2px and `#900b09` 1px in light). A focused unchecked radio (`3111:4277`) reads much like an error one (`3174:12716`).
- Hover is barely visible in light. Variants `3111:4259` (Hover, Unchecked) and `3111:4251` (Hover, Checked): fill against the resting fill is 1.09:1 and 1.13:1 (dark: 1.42:1 and 2.11:1). No WCAG minimum applies to hover; reported as measured.
- Hidden dot in the unchecked variants (for example `587:16960`) is bound to Icon/Brand/On Brand, while the visible dot uses Icon/Brand/On Brand Secondary. Not rendered, so no effect; the contract lists the token for this reason only.
